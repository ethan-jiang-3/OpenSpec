- [ ] 1.2 Document problem statement and business context — verify: primary stakeholder confirms the problem statement
- [ ] 1.3 Define scope boundaries (In Scope / Out of Scope) — verify: both scope lists are explicit
- [ ] 1.4 Document constraints and their sources — verify: every constraint cites a source
- [ ] 1.5 Define success criteria for this requirement effort — verify: criteria are observable or measurable
- [ ] 1.6 Capture desired outcomes from each stakeholder perspective — verify: every stakeholder maps to an outcome
- [ ] 1.7 Document user personas with goals and frustrations — verify: each persona has both fields
- [ ] 1.8 Capture raw user stories (verbatim, in stakeholder language) — verify: stories preserve source wording
- [ ] 1.9 Map edge cases and "what if" scenarios — verify: normal and exception paths are represented
- [ ] 1.10 Document all clarifying questions and answers — verify: each answered question records its source
- [ ] 1.11 Distinguish facts from assumptions, plan validation — verify: every assumption has a validation action

## 2. Specification

- [ ] 2.1 Draft executive summary — verify: summary states problem, scope, and outcome
- [ ] 2.2 Define all functional requirements with FR-N IDs — verify: IDs are unique and contiguous
- [ ] 2.3 Write testable acceptance criteria for each FR — verify: every FR links to at least one criterion
- [ ] 2.4 Define non-functional requirements with measurable metrics — verify: every NFR has a metric and threshold
- [ ] 2.5 Prioritize all requirements (MoSCoW) — verify: every requirement has one priority
- [ ] 2.6 Refine raw user stories into formal user story table — verify: every raw story is mapped or explicitly excluded
- [ ] 2.7 Document assumptions, dependencies, risks — verify: each item has an owner or mitigation
- [ ] 2.8 Build glossary of domain terms — verify: ambiguous terms used in specs are defined
- [ ] 2.9 List open clarifications that need stakeholder answers — verify: each question has an owner

## 3. Review & Validation

- [ ] 3.1 Run completeness check — verify: every user story maps to a requirement
- [ ] 3.2 Check FR acceptance criteria — verify: no FR lacks a testable criterion
- [ ] 3.3 Check error/exception flows — verify: each relevant FR has a failure path
- [ ] 3.4 Check empty data and edge cases — verify: applicable boundary cases are explicit
- [ ] 3.5 Run consistency check — verify: no unresolved requirement conflict remains
- [ ] 3.6 Run ambiguity check — verify: multi-interpretable wording is resolved or flagged
- [ ] 3.7 Assess feasibility of each Must requirement — verify: each Must has feasibility evidence
- [ ] 3.8 Run gap analysis — verify: findings are resolved or tracked
- [ ] 3.9 Compile prioritized clarification questions — verify: questions are ordered and assigned
- [ ] 3.10 Present review findings — verify: stakeholder responses are recorded
- [ ] 3.11 Update specs with resolutions — verify: re-run completeness and consistency checks

- [ ] 4.1 Resolve all blocking issues from review — verify: blocking-issue count is zero
