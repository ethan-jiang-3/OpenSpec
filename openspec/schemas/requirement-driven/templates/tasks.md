## 1. Proposal

- [ ] 1.1 Identify all stakeholders and their interests
- [ ] 1.2 Document problem statement and business context
- [ ] 1.3 Define scope boundaries (In Scope / Out of Scope)
- [ ] 1.4 Document constraints and their sources
- [ ] 1.5 Define success criteria for this requirement effort
- [ ] 1.6 Capture desired outcomes from each stakeholder perspective
- [ ] 1.7 Document user personas with goals and frustrations
- [ ] 1.8 Capture raw user stories (verbatim, in stakeholder language)
- [ ] 1.9 Map edge cases and "what if" scenarios
- [ ] 1.10 Document all clarifying questions and answers
- [ ] 1.11 Distinguish facts from assumptions, plan validation
- [ ] 1.12 Validate proposal with primary stakeholder — confirm ready for specification

## 2. Specification

- [ ] 2.1 Draft executive summary
- [ ] 2.2 Define all functional requirements with FR-N IDs
- [ ] 2.3 Write testable acceptance criteria for each FR
- [ ] 2.4 Define non-functional requirements with measurable metrics
- [ ] 2.5 Prioritize all requirements (MoSCoW)
- [ ] 2.6 Refine raw user stories into formal user story table
- [ ] 2.7 Document assumptions, dependencies, risks
- [ ] 2.8 Build glossary of domain terms
- [ ] 2.9 List open clarifications that need stakeholder answers

## 3. Review & Validation

- [ ] 3.1 Run completeness check — all user stories covered?
- [ ] 3.2 Verify all FRs have testable acceptance criteria
- [ ] 3.3 Check error/exception flows covered
- [ ] 3.4 Check empty data and edge case scenarios covered
- [ ] 3.5 Run consistency check — any conflicting requirements?
- [ ] 3.6 Run ambiguity check — any multi-interpretable requirements?
- [ ] 3.7 Assess feasibility of each Must requirement
- [ ] 3.8 Run gap analysis — what's missing?
- [ ] 3.9 Compile prioritized clarification questions for stakeholder
- [ ] 3.10 Present review findings to stakeholder, discuss resolutions
- [ ] 3.11 Update specs with resolutions from review

## 4. Approval & Handoff

- [ ] 4.1 Resolve all blocking issues from review
- [ ] 4.2 Present final specs for stakeholder approval
- [ ] 4.3 Document acknowledged trade-offs
- [ ] 4.4 Fill Approval section in specs (Approver, Date, Status)
- [ ] 4.5 Prepare Developer Handoff Notes in specs
- [ ] 4.6 Confirm handoff received and understood by development team
