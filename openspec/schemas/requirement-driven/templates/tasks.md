## 1. Discovery

- [ ] 1.1 Identify all stakeholders and their interests
- [ ] 1.2 Document business context and problem statement
- [ ] 1.3 Define constraints and their sources
- [ ] 1.4 Define success criteria for this requirement effort
- [ ] 1.5 Validate assumptions with primary stakeholder
- [ ] 1.6 Resolve open questions — confirm ready for elicitation

## 2. Needs Elicitation

- [ ] 2.1 Interview each primary stakeholder persona
- [ ] 2.2 Document user personas with goals and frustrations
- [ ] 2.3 Capture raw user stories (verbatim, in stakeholder language)
- [ ] 2.4 Map edge cases and "what if" scenarios
- [ ] 2.5 Document all clarifying questions and answers
- [ ] 2.6 Confirm raw needs accurately captured (stakeholder validation)

## 3. Specification

- [ ] 3.1 Draft executive summary and scope boundaries
- [ ] 3.2 Define all functional requirements with FR-N IDs
- [ ] 3.3 Write testable acceptance criteria for each FR
- [ ] 3.4 Define non-functional requirements with measurable metrics
- [ ] 3.5 Prioritize all requirements (MoSCoW)
- [ ] 3.6 Document assumptions, dependencies, risks
- [ ] 3.7 Build glossary of domain terms

## 4. Review & Validation

- [ ] 4.1 Run completeness checklist — all stories covered?
- [ ] 4.2 Run consistency check — any conflicting requirements?
- [ ] 4.3 Run ambiguity check — any multi-interpretable requirements?
- [ ] 4.4 Assess feasibility of each requirement
- [ ] 4.5 Run gap analysis — what's missing?
- [ ] 4.6 Compile prioritized clarification questions for stakeholder
- [ ] 4.7 Present review findings to stakeholder, discuss resolutions
- [ ] 4.8 Update spec.md with resolutions from review

## 5. Signoff & Handoff

- [ ] 5.1 Resolve all blocking issues from review
- [ ] 5.2 Present final spec for stakeholder approval
- [ ] 5.3 Document acknowledged trade-offs
- [ ] 5.4 Prepare developer handoff notes
- [ ] 5.5 Confirm handoff received and understood by development team
