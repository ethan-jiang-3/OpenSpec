## 核心主题

v1.9.0 的重心是**校验/归档更诚实、工具投递再扩一家、fork/重建更保真**：

- 新工具 **Command Code**（先 skills-only，再补 `/opsx-*` command adapter）。
- 新命令面 **`openspec validate --archived`**：opt-in，检查 archive 里未勾完的 tasks，给 CI / pre-commit。
- bulk `list` / `validate --all|--changes|--specs` / `schemas` 在项目外不再假装空项目通过。
- scenario-loss 认每一个 `####` 子标题，不只是 `#### Scenario:`。
- apply 指令要求超出 spec 的工作停下来报，不能默默缩小范围。
- archive 非 TTY 不再打 ANSI；重建 spec 保留 `## Requirements` 周围空行、文件末尾恰好一个换行。
- `schema fork` 原地改 YAML，保留注释、block-scalar 和 key 顺序。
- `openspec update` 不再用遗留 Codex 升级去抢 `.agents` 的 ownership。

## 按领域拆解

### 工具投递：Command Code

| 事实 | 机制 | 对本仓库的意义 |
|---|---|---|
| `--tools command-code` 装 skills | `AI_TOOLS` 增加 `command-code`，`skillsDir: '.commandcode'` | 又一家 adapter-backed 宿主；skills 在 `.commandcode/skills/`，skill 面调用 `/openspec-*`。 |
| command adapter 写 `/opsx-*` | `src/core/command-generation/adapters/command-code.ts` 生成 `.commandcode/commands/opsx-<id>.md` | 默认 `both` 投递时 skills 与 slash command 并存；command 名是 `/opsx-<id>`（平铺，与 Cursor/OpenCode 同类）。 |

新增工具：**Command Code**。MiniMax / Rovo / Copilot / `agents` 目标不变。

### Validate：`--archived`、root 诚实、scenario-loss 放宽匹配

- **`openspec validate --archived`**：独立 scope，不改现有 `validate` 调用。扫 `changes/archive/`，用共享 `getTaskProgressDetailForChange` 计数；未勾完或 tasks 文件读失败 → ERROR、exit 1。不重验已应用的 delta。见 `src/commands/validate.ts` 的 `runArchivedTaskValidation`。
- **bulk 拒绝 implicit root**：`validate --all/--changes/--specs` 设 `allowImplicitRoot: false`；`list` 只在 cwd 仍有遗留 `openspec/project.md` 时允许 implicit。项目外跑这些命令不再 exit 0 报空结果。单条 `validate <name>` 不变。
- **`openspec schemas`** 走 canonical root selection，接受 `--store <id>`，拒绝 `--store-path`。
- **scenario-loss**：`SCENARIO_HEADER = /^####\s+/`。任何 requirement 下非 fence 的 `#### ` 子标题都算 scenario（如 `#### Edge case`）。比较时剥可选 `Scenario:` 前缀和 CommonMark 收尾 `#`。作者仍应写 `#### Scenario:`，但 loss guard 不再漏掉未标 `Scenario:` 的四级标题。
- **#1523 task-numbering**：0005 已覆盖；v1.9.0 只是正式打进 release note。

### Apply：超出 spec 的工作必须停下来报

`getApplyInstructions()` 新增 pause trigger：任务需要的工作超出 spec/tasks 描述，或想 drop / narrow / defer / accept exceptions 来塞进范围 → **surface the added scope and pause**。勾 `- [x]` 只在指定行为全部落地之后。这是模板文本，不是 CLI 硬校验。

### Archive：非 TTY 与 spec 重建保真

- 非 TTY（stdin 或 stdout 不是终端）时，confirm 走纯文本、无 ANSI；无 change 名时要求先传入名字，不画菜单。`--yes` 与管道回答行为不变。
- 重建 spec 保留 `## Requirements` 周围空行，文件以恰好一个 LF 结尾（修 Markdown whitespace 检查失败）。
- 遗留 Codex 升级不再覆盖已由 `agents` 目标占用的 `.agents` 树；跳过时也不删该工具的 repo-local legacy 文件。

### Schema fork：YAML 保真

`openspec schema fork` 用 YAML Document API 原地改名，不再 parse/re-serialize。注释、literal `|` vs folded `>`、key 顺序保留。

### 其他

- `openspec init` 只对 IDE 内嵌工具（Cursor、GitHub Copilot、Continue、Cline）提示 Restart IDE；Claude Code / Codex / Gemini CLI 不再提示。
- 首次遥测披露在 `--json` 时推迟到下一次非 JSON 运行，避免污染机器输出。
- `openspec config` 的 workflow picker 给 `update` 补了友好标签。
- 依赖/CI：js-yaml、nanoid overrides；pnpm action-setup 等。
