# 同步 0002：v1.4.1 → v1.5.0

**日期**：2026-07-07

**hash 范围**：`1b06fdd` → `5956a8e`

**提交数量**：11（不含 changeset 发版自动化提交）

**版本标签**：v1.5.0

## 核心主题

这是一个**架构重构版本**。v1.4.0 引入的 workspace beta + initiatives + context store 三条线被统一为一个 **stores** 模型。同时附带一次文档全面重做和若干质量修复。

## 按领域拆解

### Stores：Workspace/Initiative/Context Store 三合一（BREAKING）

| 维度 | 变更 |
|------|------|
| 概念模型 | `workspace` + `initiative` + `context-store` → 统一为 **store**（仓库注册）+ **workset**（工作集）+ **reference**（仓库引用） |
| 新增命令 | `openspec store`（管理注册仓库）、`openspec context`（查看工作集）、`openspec workset`（管理个人工作集）、`openspec doctor`（健康检查） |
| 删除命令 | `openspec workspace`（全部子命令）、`openspec context-store`、`openspec initiative` |
| 新增核心模块 | `core/store/`（foundation, operations, registry, git）、`core/worksets.ts`、`core/root-selection.ts`、`core/references.ts`、`core/relationship-health.ts`、`core/working-set.ts`、`core/openers.ts`、`core/file-state.ts` |
| 删除核心模块 | `core/workspace/`（foundation, registry, openers, skills, state-io, open-surface, legacy-state, link-input）、`core/context-store/`（binding, foundation, operations, registry）、`core/collections/initiatives/`（collection, operations, resolution, schema, templates）、`core/collections/runtime.ts` |
| Schema 删除 | `schemas/workspace-planning/` 整个目录及其模板 |
| Spec 删除 | `openspec/specs/workspace-foundation/`、`workspace-open/`、`workspace-links/`、`workspace-change-planning/`、`openspec-conventions/`、`cli-config/`、`cli-update/` 等 |
| 新增 Spec/Work | `openspec/work/` 下大量 stores 相关设计文档（capstone, slices, roadmap, direction） |

**意义**：v1.4.0 的 workspace beta 是「多仓库协同」的第一次尝试，但 workspace + initiative + context store 三个概念各自演进后产生了概念重叠和接口不一致。v1.5.0 把它们统一成 **store 模型**——一个 store 就是一个注册进来的仓库，项目通过 `references` 声明依赖哪些 store，agent 通过 `context` 命令了解当前工作集。这是对 v1.4.0 路线的一次**收敛式重构**，不是简单的增量叠加。

## 对 `_digested/` 的影响

**这是消化材料自 v1.3.0 以来面临的最大冲击。** 上一次同步（0001）指出「workspace 是值得深入消化的主题」——但 v1.5.0 把 workspace 整个删了。这意味着：

| 子目录 | 影响程度 | 说明 |
|--------|----------|------|
| **`system/`** | 🔴 严重 | 整体系统模型中的 workspace 概念已不存在。`system/` 中对 workspace、context store、initiative 的描述需要替换为 store + workset + reference 模型。新增的 `root-selection`、`relationship-health`、`working-set` 形成了新的「上下文组装」管线，需要消化。 |
| **`spec_cli/`** | 🔴 严重 | CLI 命令体系大幅变化。`workspace` 及其全部子命令被删除，新增 `store`、`context`、`workset`、`doctor` 四个命令。`spec_cli/` 中的命令全景图需要重画。 |
| **`schema/`** | 🟡 中等 | `schemas/workspace-planning/` 被删除，但 schema 系统本身的机制未变。影响主要是内容层面（少了一个内置 schema），不是机制层面。 |
| **`internal-spec-driven/`** | 🟡 中等 | `archive` 和 `validate` 的 resolution 逻辑变化。核心命令（explore/propose/apply/archive）的整体流程未变，但 archive 的内部实现需要重新消化。 |
| **`mechanisms/`** | 🔴 严重 | `mechanisms/` 中若有 workspace 相关章节则全部过时。新增的 store 机制（`core/store/`：foundation/operations/registry/git）是新的消化对象。`worksets`（个人工作集管理）也是新主题。 |
| **`specs_truth/`** | 🟡 中等 | resolution 收敛（validate/view/archive 统一路径）直接影响 spec delta 的解析和校验逻辑。`specs_truth/` 中的「为什么失真」「怎么修」可能受 resolution 逻辑变化影响。 |
| **`_coverage/`** | 🔴 严重 | 源码文件大量增删（235 files changed），覆盖矩阵需要全面刷新。核心模块重命名（`context-store` → `store`）和删除（`workspace/`、`collections/initiatives/`）导致旧的覆盖映射失效。 |
| **`_faq_on_digested/`** | 🟡 中等 | 上次同步指出的 `schema-article-driven` 条目受 workspace schema 影响——现在 workspace schema 整个没了，该条目可能从「需要验证」变为「不再适用」。 |

### 优先级建议

1. **第一优先**：`_coverage/` — 覆盖矩阵刷新，建立新的源码→消化文章映射。这是后续所有消化工作的基础设施。
2. **第二优先**：`mechanisms/` + `system/` — store 模型替代 workspace 是整个 v1.5.0 的核心故事，需要新的消化文章。
3. **第三优先**：`spec_cli/` + `internal-spec-driven/` — 命令变更和 resolution 更新。
4. **可选**：`schema/` + `specs_truth/` — 影响相对局部。
