## 三个版本的核心主题

- **v1.14.1 — apply 完成语义与归档错误语义（patch）**：`all_done` 不再等同"可归档"，改为"跟踪任务已完成，归档前请复核/验证"；archive 的 retirement 清理失败有了独立错误码 `archive_retirement_cleanup_failed`；CLI 每个命令改为按需加载实现（`--help` 从 485 模块降到 24）；`validate --strict` 对超长 requirement（500 字符）失败；specs 逐文件写入；verify 按输出路径发现 spec/design 工件；view 彻底移除归档区。
- **v1.14.2 — 路径与内容的边界收紧（patch）**：`openspec/`、`changes/`、`specs/` 允许是项目内 symlink；brace 嵌套 >16 层提前拒绝；explore 的捕获表限定默认 schema；Tab 补全从 344 模块降到 48 且不记遥测；update 放宽 glob 新文件例外；verify 对 REMOVED requirement 先读基线再搜索；validate/archive 对"delta 里不会被带走的文本"告警；`.openspec.yaml` 的小写 `x-` 扩展键不再报未知。
- **v1.14.3 — 安全与稳健性收尾（patch）**：`fast-glob` → `tinyglobby` + `brace-expansion` + `picomatch`，安装不再引入未修补的 `braces`；`spec.md` 允许指向项目内任意位置的 symlink；propose/ff/continue 的 glob 工件路径必须落在 change 目录内；零宽 TTY 下 `validate --all` 不再挂死；website 预览改用零依赖 `scripts/preview.mjs`。

### 1. 安全：glob 引擎更换与 brace 预算（v1.14.2 + v1.14.3）

| 提交 | 变更 |
|------|------|
| `e33245d2`（#2103） | 依赖层替换：移除 `fast-glob`，新增 `tinyglobby@^0.2.17` + `brace-expansion@^5.0.12` + `picomatch@^4.0.4`（+ dev `@types/picomatch`）。安装后不再有 `braces`，GHSA-vfj7-8cjw-p6xm 不再经由本包出现在下游 `pnpm audit` |
| `7acf2820`（#2061） | `src/core/artifact-graph/outputs.ts` 新增 `assertBraceNesting`：镜像 braces 解析器（`[...]` 与引号内为字面量、`(` 与 `{` 同样计深、关闭符只闭合同类最内层），嵌套 > `MAX_BRACE_NESTING`（16）直接报错，任何 glob 匹配之前 |
| `e33245d2`（#2103） | 新增 `MAX_BRACE_EXPANSIONS = 1024` 与 `assertExpansionBudget`：`{a,b}` 重复十余次或 `file-{1..5000}.md` 这类展开会被拒绝，错误文案 `Artifact output pattern expands to more than 1024 patterns: ...`。实现上做了**逐个顶层组展开**（`findTopLevelExpansion`/`hasTopLevelExpansion`）而不是交给 brace-expansion 一次性递归——避免 `{a,{a,{a,b}}}` 这种 16 层模式在超时前跑不完；同时绕开 brace-expansion 5 在 `{draft}` 在前时把后续范围当字面量的行为。字面量 `{...}` 用 NUL 前缀哨兵 `\u0000<` / `\u0000>` 承载，因为 `resolveArtifactOutputPath` 的 `path.join` 会先拒绝 NUL 字节，无法被 `generates` 值伪造 |

配套机制变化：
- `globBase()` 取代 fast-glob 的 `generateTasks().base`：静态目录前缀仍然先做 `assertPathWithin(changeDir, ...)`；**绝对模式保持绝对**（否则 `path.resolve(changeDir, '/etc/*')` 会被重基到 change 目录里而绕过包含检查）。
- `assertGlobDirectoryTraversal` 里的目录枚举从 `fg.sync` 换成 `listDirectoryMatches()`（`fs.readdirSync` + `picomatch` 单段匹配），并显式处理 `.`/`..` 段——`**/../` 现在在 glob 跑起来之前就被限制。
- `ARTIFACT_GLOB_OPTIONS`：`braceExpansion: false`（先自行展开，留下的 `{draft}` 仍作字面量）、`expandDirectories: false`（迁移语义对齐：目录模式不再长尾巴 `/**`）、`followSymbolicLinks: true`、`onlyFiles: true`。
- 依赖钉版：root workspace override `brace-expansion@<5.0.12: '>=5.0.12 <6'`（GHSA-6j4f-fj2g-mc7p / GHSA-qhr7-859c-m2p7 / GHSA-q2hr-2g5m-vwhr）；新增 `shell-quote@>=1.8.4 <1.11.0: '>=1.11.0 <2'`（仅 dev）。website workspace 的 `brace-expansion`/`fast-uri` 钉版**被删除**——因为 `serve` 依赖已移除。

### 2. 路径边界：symlink 到底能指多远（v1.14.2 + v1.14.3）

| 提交 | 变更 |
|------|------|
| `90c95c2a`（#2052） | archive 前置检查从 `assertPathWithin` 改为可选的 `assertPathWithinAllowingLinkedLeaf`：`openspec/`、`changes/`、`specs/` 本身可以是 symlink（指向另一个目录，比如共享文档仓库），但其**父目录**仍须受限，且链接必须 resolve 到已存在的路径（悬空链接报错）。`archive/` **不允许**成为链接（`allowLinkedLeaf=false`），它必须留在所在 changes 目录内 |
| `90c95c2a`（#2052） | archive 校验归档后 delta 时用 `canonicalChangeDir`（`canonicalizeExistingPath(changeDir)`）算相对路径——`update.source` 是 canonical 的，`changes/` 自身是链接时原先 `path.relative(changeDir, ...)` 会算错 |
| `87a69a2b`（#2101） | 新模块 `src/utils/spec-path-containment.ts`：`assertSpecFileWithin(root, file)` 与 `assertDiscoveredSpecFile(specsRoot, file)`。能力目录内的 `spec.md` 允许是指向**项目内**任意位置的相对 symlink（典型场景：spec 文件住在产品文档旁边）；解析到项目外仍拒绝；悬空链接报错 |
| `87a69a2b`（#2101） | `findProjectRoot()`：从 specs root 向上找 `<X>/openspec`，且下一层必须是 `specs` 或 `changes`——这两条同时成立才算"规划根"，父目录才是项目边界。**这个限定很重要**：否则放在 `~/openspec/my-store` 的 store 会把 `~` 当成边界。经由其他途径到达的 specs root（如按路径给出的 store）没有可命名的项目，包含检查停在 specs root |
| `87a69a2b`（#2101） | `assertDiscoveredSpecFile` 刻意**不**从文件自身的能力目录重新推导信任根：能力目录在路径解析后被换成链接时必须拒绝，而不是重新信任。字面包含检查失败后，只有当能力目录本身仍在 specs root 内（词法判断）才允许把能力目录当作文件自己的信任根 |
| `87a69a2b`（#2101） | 写侧加固 `writeUpdatedSpec()`：`verifiedTarget = canonicalizeExistingPath(update.target)` 钉住已验证的文件；`beforeMutate` 之后**重新**做包含检查，并拒绝 canonical path 已改变的情况（`Spec target for '<id>' changed before it could be written`）——一个在检查后被重新指向的链接不能把写入导到未经校验的文件 |

`discoverSpecFiles` 的判定逻辑被抽走：能力内 `spec.md` 链接的"能指多远"现在统一由 `assertSpecFileWithin`/`assertDiscoveredSpecFile` 决定，拼写复杂度不再散落在 discovery 里。
