## 按版本拆解

### v1.3.1 (Patch — 5 个 bug fix)

| 领域 | 变更 |
|------|------|
| 路径规范化 | artifact 路径用原生 `realpath` 解析，解决 symlink + 大小写不敏感文件系统的错配 |
| Glob apply | `apply` 中 glob artifact 输出现在正确解析 |
| 隐藏需求检测 | 被 fenced code block 包裹的需求也能在 main spec 中被检测到 |
| JSON 输出 | `--json` 时 spinner 的 stderr 输出不再污染 JSON，agent 可安全解析 |
| 遥测静默 | PostHog 网络错误被静默处理（1s 超时 + 禁重试），防火墙环境不再报错 |

**意义**：把 v1.3.0 的几个明显 bug 修了，主要是让 agent 调用更可靠（JSON 解析、路径匹配、需求检测）。

### v1.4.0 (Minor — 新功能 + workspace beta)

| 领域 | 变更 |
|------|------|
| **Kimi CLI** | 新增 Kimi CLI 的 skills-only 支持 |
| **Mistral Vibe** | 新增 Mistral Vibe 的 skills-only 支持 |
| 需求解析 | requirement header 解析改为大小写不敏感 |
| Oh-my-zsh | 修复 zsh completion 在 omz 的 compinit 下安装失败 |
| 校验提示 | 当 SHALL/MUST 只在 header 出现时，validate 给出更精确的提示 |
| Sync workflow | `/opsx:sync` 纳入默认 core profile，新项目默认生成 sync 命令 |
| **Workspace beta** | 新增多仓库 workspace 支持（见下） |
| Community schemas | README 新增社区 schema 章节 |
| 模型推荐 | 更新推荐的高推理能力模型列表 |

**Workspace beta 详细**（这是一大块新能力）：

- `workspace setup` — 创建 workspace 配置，注册仓库
- `workspace open` — 打开 workspace 上下文给 agent
- `workspace create` — 从 proposal 创建 workspace 变更
- `workspace change planning` — workspace 级变更规划工作流
- `context stores` — agent 上下文存储机制
- `initiative views` — 跨仓库变更的可视化
- 大量 Windows 路径兼容修复

**意义**：OpenSpec 从「单仓库 spec-driven」扩展到「多仓库 workspace」。这是一个重要的架构升级 —— 之前只能管理一个项目的 spec 和 change，现在可以跨仓库协同规划变更。workspace 仍标记为 beta。

**意义**：workspace beta 的快速修复，解决和现有项目的兼容性问题。
