## 1. 2.0.0：只装 skills，一个共享文件夹（#2223）

### 四个变化

| 项 | 1.x | 2.0 |
|---|---|---|
| skills 位置 | 每个工具自己目录一份拷贝 | `.agents/skills/` 一份真身，其他工具用链接 |
| 命令文件 | 与 skills 并列安装 | **不再生成** |
| `delivery` 设置 | skills / commands / both | **退役**：一律 skills |
| Amazon Q Developer | prompt 文件 + skills | **退役**：读不了 skills |

### 代码层面的落地

- 命令生成能力被整体移除：`shouldGenerateCommandsForTool` 在 2.1.1 里**已不存在**
- `src/core/templates/optional-workflow.ts` 删除
- `init.ts` +378/−352、`update.ts` +313/−403 —— 两个主流程都是重写级改动
- `shared-skill-target.ts` +143/−237：共享目标的判定逻辑换代

### 一个容易被忽略的细节：适配器层没删

`src/core/command-generation/adapters/` **35 个文件仍在**。但它们的职责变了：

> 不再生成命令文件，只用来**知道旧文件曾经写在哪里**。

调用方只剩 `command-surface.ts`、`migration.ts`、`command-reconcile.ts`、`tool-detection.ts`、`profile-sync-drift.ts`、`released-output-sweep.ts`——全是清理与路径解析。**能力删掉了，路径知识留下了。**

这也解释了为什么指纹库在上一轮那么重要：2.0 要按路径 + 内容做大规模删除，而「内容」正是靠指纹判断的。

### Windows 的代价

链接是提交进仓库的。Windows 用户需要 `git config --global core.symlinks true` 并开启开发者模式，否则链接会被 checkout 成普通小文件；`openspec update` 会把它替换成一份拷贝（功能可用，只是失去去重）。

## 2. 安装层外包给 `skills` 包

这是本版最该记下的一项架构决定。

`package.json` 新增**运行时依赖**：

```json
"skills": "1.8.1"
```

`src/core/skill-installer.ts` 直接调用：

```ts
import { installSkills, removeSkills } from 'skills';
```

同时 `global-skills.ts` 用它的 `getSupportedAgents()` 来查各工具的技能目录约定。

**含义**：OpenSpec 不再是「自己实现 34 套工具目录规则」的项目，而是「用第三方的跨工具安装器 + 自己的内容」。1.17.0 里那 34 个适配器是自建的代价，2.x 把它交给了上游生态。

配套的三个新文件：

| 文件 | 行数 | 职责 |
|---|---|---|
| `skill-installer.ts` | 126 | 生成期望内容、调用 `skills` 安装/移除、校验 |
| `shared-skill-install.ts` | 177 | 共享目录的安装与比对 |
| `skill-links.ts` | 187 | 每技能一条相对链接；建不了链接就退化成拷贝 |

`skill-links.ts` 的分类很细，`SkillLinkSpot` 有五种状态：`missing` / `link` / `copy` / `released` / `user`。其中 `released` 指「早期发布写下的未改动拷贝，或 git 把链接 checkout 成了文件」——可以安全替换；`user` 是「改过的拷贝、别的链接、多余文件」——一律保留。

它复用了 1.17.0 的指纹设施：`isReleasedGeneratedContent`。

## 3. 2.1.0：全局 skills（#2241）

新增 `global-skills.ts`（187 行）+ `known-projects.ts`（116 行）+ `project-skills-scope.ts`（54 行）。

- 技能作用域变成 `global | project`，由 `openspec/config.yaml` 记录选择，团队不再被重复询问
- `known-projects.ts` 维护「本机用过 OpenSpec 的项目」清单，供后续全局刷新用；注释写明它是**纯本地文件、可读可写失败都当空处理、任何命令都不会因为它失败**
- 非交互环境（CI、agent 调用）**不会弹问题**，就地刷新

## 4. 工具退役机制

新增 `retired-tools.ts`（109 行）+ `config.ts` 里的 `RETIRED_TOOLS` 表。

退役工具的结构化定义：

```ts
{
  id: 'amazon-q',
  name: 'Amazon Q Developer',
  folder: '.amazonq',
  reason: "it can't load skills, and AWS is retiring it in favor of Kiro",
  successor: 'kiro',
  successorName: 'Kiro',
}
```

三个行为：

1. `init --tools amazon-q` 直接报错，并给出 `openspec init --tools kiro` 的替代命令
2. 不计入「已配置工具」
3. 旧项目里它留下的文件照常清理：OpenSpec 生成的删掉，用户改过的保留并列出

**这是把「不支持的生态」做成了可维护的数据结构**，而不是散在代码里的特判。
