## 核心主题

v1.11.0 的重心是**差异化审视与批量状态检查**：                                                                

- **`openspec show <change> --diff`** — 隔离 delta 里真正变化的行，不再是重贴整个 requirement 块。
- **`openspec status --all`** — 一条命令扫全部 active change，不崩溃于单个故障。
- **Explore 写入前必须获得明确范围限定确认** — 防止 agent 将设计讨论误认为授权。
- **Antigravity 迁移到 `.agents/`** — 与 Codex、Zed、vendor-neutral agents 共享技能根目录，`resolveSharedSkillWriters` 仲裁写入权。
- **`openspec validate` 报出 archive 留下的 Purpose 占位符** — 默认 warning，`--strict` 才 fail。
- **Archive rename 保留 requirement 原始顺序**。
- **`schema init --default` 写入 loader 实际读取的 schema 键**，失败时回滚。
- **Fish completion 不再回退到文件名建议**。
- **Explore 图例改纯 ASCII**，跨终端对齐一致。
- **上流删除了两个内置 schema**（`agent-dev-driven`、`requirement-driven`）——它们不是 spec-driven 核心 schema，长期未维护，v1.11.0 移除了它们。

## 按领域拆解

### `openspec show <change> --diff`（新功能）

| 维度 | 变更 |
|------|------|
| 新增模块 | `src/utils/requirement-diff.ts` — 使用 `diff` 库的统一 diff 算法，对比 delta requirement 与 main spec 对应块 |
| 新增测试 | `test/commands/show-diff.test.ts`（678 行，详尽覆盖 MODIFIED/RENAMED/ADDED/REMOVED/--store/--json/inexact match） |
| CLI 变更 | `openspec show <change> --diff` 对 MODIFIED requirement 输出彩色 unified diff（绿色新增、红色删除）；ADDED 输出全文；REMOVED 输出 Reason/Migration note；RENAMED 输出 FROM/TO |
| JSON 输出 | `--json --diff` 保留既有 payload 形状，在 MODIFIED delta 上加 `diff` 和 `warning` 字段 |
| Store 支持 | `--store <id>` 解析 main spec 指向该 store |
| 不输 diff | REMOVED 的 Reason/Migration 不是 diff（没有可对照的旧块），ADDED 输出全文 |

**意义**：MODIFIED requirement 必须完整重述自己保留的每个 scenario，导致 delta 审阅者看到的文本和 main spec 几乎一样。「改了哪一行」要靠人手工做文件 diff。`--diff` 把真实变更行隔离出来。对材料的影响：`_digested/spec_cli/` 中的 show 命令面、`_digested/internal-spec-driven/` 的 delta 构造解读、`_digested/specs_truth/` 的「spec 失真」分析都可能引用——现在你有程序化手段看清失真。

### `openspec status --all`（新功能）

| 维度 | 变更 |
|------|------|
| CLI 变更 | `openspec status --all` 扫 `openspec/changes/` 下全部 active change，一个进程返回全部状态 |
| JSON 输出 | `{ "changes": [<status>, ...], "root" }` envelope，按 change name 排序稳定 |
| 故障处理 | 某 change 加载失败时贡献 `{ "changeName", "status": [diagnostic] }` 替代而非中止全扫 |
| 退出码 | 部分失败在 text 和 JSON 模式均 exit 1，同时保留完整 JSON envelope |
| 互斥 | `--all` 与 `--change <name>` 互斥 |

**意义**：多个 active change 的项目不需要逐个 `openspec status` 调用了。依赖影响：`_digested/spec_cli/` 中 status 命令描述，`_digested/workflows/` 中的 workflow 状态检查。

### Explore：写入前必须获得明确的、范围限定的确认

| 维度 | 变更 |
|------|------|
| Explore template | `src/core/templates/workflows/explore.ts` — 增加写入前确认步骤 |
| SKILL.md | `skills/openspec-explore/SKILL.md` — Guardrails 节重写 |
| 核心规则 | 只读命令和工具不需要确认。在第一次写操作之前——包括 `openspec new change` 或其他写文件的命令——命名拟创建/编辑的 artifacts 或文件，ask a direct yes/no question，在单独的用户消息中等待确认 |
| 范围限定 | 该确认仅覆盖已描述的范围；扩展前需要另一次确认。对设计/澄清问题的回复不是写入授权 |
| 非写入变更 | 不创建 artifact（仅只读探索）仍保持无摩擦 |

**意义**：用户回答 agent 的设计问题不再被解读为「同意写入」。这是 explore 工作流的重要安全护栏。依赖影响：所有涉及 explore 流程的消化文章都需要更新行为描述。

| 维度 | 变更 |
|------|------|
| 工具定义 | `src/core/config.ts` — `antigravity` 的 `skillsDir` 从 `.agent` 改为 `.agents`，增加 `legacySkillsDirs` 和 `detectionPaths` |
| 核心仲裁 | `src/core/shared-skill-target.ts` — 新增 `resolveSharedSkillWriters()`，从一组工具中为每个物理 skills root 选出一个写入者 |
| Init 重构 | `src/core/init.ts` — 共享 root 仲裁逻辑重写：不再硬编码 Codex/Zed/agents 三元组，改为通用化的 `resolveSharedSkillWriters` |

**意义**：Antigravity 从独立 `.agent/` 根迁入 `.agents/` 共享树，遵循 Codex 与 Zed 已建立的 one-writer 规则。这是跨工具共享 skill 根的重大演进——不再是 Codex/Zed/agents 三方协议，而是通用仲裁策略：skills-native 渲染器优先，已存在的 owner 优先，Codex 作为新 root 的默认写入者。依赖影响：`_digested/mechanisms/` 中的工具投递文、`_digested/system/` 中的 agent 协议文需要大幅更新共享 root 仲裁部分。

### Validate：Purpose 占位符检测

| 维度 | 变更 |
|------|------|
| 新增模块 | `src/core/validation/purpose-placeholder.ts` — 精确检测 archive 写入的 `TBD - created by archiving change ...` 占位符 |
| 新增常量 | `PURPOSE_PLACEHOLDER_PREFIX` = `'TBD - created by archiving change '`，`PURPOSE_PLACEHOLDER_SUFFIX` = `'. Update Purpose after archive.'`，和 writer 使用同一份定义 |
| 检测规则 | 两种计数：① 生成的占位符句子（通过首尾常量匹配）；② 以 `TBD` 或 `TODO` 开头的 Purpose（不含更长词如 `TBDs`） |
| 级别 | `WARNING`（默认通过，`--strict` 报 error） |
| 边界 | fence 内引用不计；`TBD` 在句子中间不留（如 `"The retry budget is TBD"` 是有效 Purpose）；空 Purpose 由已有检查处理，不重复报 |

**意义**：archive 为新建 capability 写入 placeholder 后，human 忘记更新，所有命令仍报 success。现在 validate 会在 warning 层提醒。依赖影响：`_digested/internal-spec-driven/` 的 archive 流程、`_digested/specs_truth/` 的 spec 质量问题检测、`_digested/schema/` 的 validate 规则表。

**意义**：RENAMED + MODIFIED 同一条时，rename 不会把块移到 spec 尾部，保持 archive diff 可读。依赖影响：`_digested/internal-spec-driven/` 中的 archive 操作细节。

## 验收基线

同步完成后至少确认：

```text
git log --oneline HEAD~3..HEAD    # merge + restore 两个提交
node -p "require('./package.json').version"  # 1.11.0
openspec --version                # PATH 环境独立升级
```

并运行与 show --diff、status --all、explore template、Antigravity、schema init --default、Purpose placeholder、Fish completion、archive rename 对应的定向测试。
