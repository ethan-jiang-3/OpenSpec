# 源码地图与扩展点

## 读源码的入口顺序

建议不要从 `src/cli/index.ts` 一路线性读。更有效的顺序是：

1. 先看 `src/core/planning-home.ts`，明白 repo root 如何判定。
2. 再看 `src/commands/workflow/`，明白 agent runtime API。
3. 再看 `src/core/artifact-graph/`，明白 schema 如何变成状态图。
4. 再看 `src/core/init.ts`、`src/core/update.ts`，明白投递层。
5. 最后看 `src/core/store/` + `src/core/references.ts` + `src/core/root-selection.ts`，明白多仓库 store 模型。

## 常见扩展点

### 加一个新的 workflow

主要入口：

- `src/core/templates/workflows/<id>.ts`
- `src/core/profiles.ts`
- `src/core/shared/skill-generation.ts`

如果它需要新的 CLI runtime 数据，再看 `src/commands/workflow/`。

### 加一个新的 coding agent

v2.1 起 OpenSpec 把工具目录规则委托给运行时依赖 `skills` 包（`getSupportedAgents()`），接入路径和 1.x 完全不同：

- **如果上游 `skills` 包已收录该工具**：升级 `package.json` 的 `skills` 依赖即可，`src/core/config.ts:164-168` 会自动把未出现在 `existingTools` 里的工具追加进 `AI_TOOLS`，并根据 `agent.universal` 自动决定直读 `.agents/skills/` 还是归入 `SKILL_LINKED_TOOL_IDS` 建相对链接。
- **如果需要定制展示名、检测路径或别名映射**：在 `src/core/config.ts` 的 `existingTools` 补充条目（如 `detectionPaths`、`legacySkillsDirs`、`searchAliases`、`setupNote`、`requiresIdeRestart`），若 OpenSpec 公开 `--tools` ID 与 `skills` 包的 `agent.id` 不同，在 `installerAliases` 登记映射；若该工具连 `skills` 包都尚未收录，它会回退到 `'universal'`（只写 `.agents/skills/` 并附 `setupNote` 提示手动链接）。
- **不再做的事**：**不要**在 `src/core/command-generation/adapters/` 新增 command adapter（v2.0.0 起不再生成任何 command 文件，adapters 只用于清理 1.x 遗留文件）；也**不存在** 1.x 的 `resolveSharedSkillWriters` / `reconcileSharedSkillTargets` 共享根写权仲裁（项目级真身统一只有 `.agents/skills/` 一份，`.openspec-target` 按行记录所有已配置工具）。
