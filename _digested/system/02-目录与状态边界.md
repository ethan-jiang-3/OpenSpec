# 目录与状态边界

## 一句话

OpenSpec 的“状态”不是集中在一个配置文件里，而是按职责分散在几类目录里。判断某个文件重要不重要，先问它属于哪一层：项目事实、工作流定义、投递层、本机视图，还是团队协调上下文。

## repo-local 项目状态

```text
repo-root/
└── openspec/
    ├── specs/
    ├── changes/
    ├── config.yaml
    └── schemas/
```

| 路径 | 本质 | 是否是项目事实 |
|------|------|----------------|
| `openspec/specs/` | 当前 capability spec 基线 | 是 |
| `openspec/changes/<name>/` | 一次增量 change 工作区 | 是，直到 archive |
| `openspec/changes/<name>/.openspec.yaml` | 单次 change 的 schema 绑定等 metadata | 是 |
| `openspec/config.yaml` | 项目级默认 schema、context、rules、references、`skillsScope` 等 | 是，但它是配置/提示层，不是 capability spec |
| `openspec/schemas/<name>/` | 项目本地 schema 定义 | 是，属于工作流定义 |

最容易想错的是 `config.yaml`。它不是项目能力清单，也不是 artifact DAG。它主要参与两件事：新建 change 时提供默认 schema；生成 instructions 时注入 context/rules。

## schema 与模板状态

schema 可以来自三类位置：

```text
repo-root/openspec/schemas/<name>/
getGlobalDataDir()/schemas/<name>/
package/schemas/<name>/
```

schema 目录的核心文件是：

```text
schema.yaml
templates/*.md
```

`schema.yaml` 定义 artifact id、输出路径、依赖关系、instruction、apply requires/tracks。template 是 artifact 输出内容的起始形状，不等于 schema 本身。

更细的字段和解析优先级见 `../schema/`，这里不展开。

## global config 与 global data

OpenSpec 有两个遵循 XDG Base Directory 规范的全局根：

| 根 | 来源函数与默认路径 | 保存什么 |
|----|--------------------|----------|
| global config dir | `getGlobalConfigDir()`（`$XDG_CONFIG_HOME/openspec/`；Unix/macOS 回退 `~/.config/openspec/`，Windows 回退 `%APPDATA%/openspec/`） | `config.json`：`profile`、`workflows`、`skillsScope`、`defaultStore`、`openers`、`telemetry` 等用户级配置（1.x 另有 `delivery`，v2.0.0 起退役） |
| global data dir | `getGlobalDataDir()`（`$XDG_DATA_HOME/openspec/`；Unix/macOS 回退 `~/.local/share/openspec/`，Windows 回退 `%LOCALAPPDATA%/openspec/`） | 用户级数据：`stores/registry.yaml`、`worksets/worksets.yaml`、用户级 `schemas/`、`projects.json`（本机用过 OpenSpec 的项目列表）、`global-skills.lock`（全局技能安装互斥锁）、standalone 的 `binary-schemas/` |

源码入口：

- `src/core/global-config.ts`
- `src/core/config-schema.ts`
- `src/core/known-projects.ts`

global config 影响投递层：启用哪些 workflow（`profile` / `workflows`），以及新项目 `init` 默认把 skills 装在本机全局还是项目内（`skillsScope`，默认 `'global'`）。它不保存某个 repo 的业务 specs。

## agent 集成目录

v2.x 起 OpenSpec **只投递 skills**（不再生成 1.x command 文件），分为两层作用域：

- **全局作用域（新项目 `init` 默认）**：真身写在 `~/.agents/skills/`，并为需独立全局目录的工具创建对应目录/链接；安装记录写入 `$XDG_STATE_HOME/skills/.skill-lock.json`（未设时回退 `~/.agents/.skill-lock.json`），并发安装由 `<globalDataDir>/global-skills.lock` 串行化。
- **项目作用域（`--scope project` 或已有项目级技能）**：`.agents/skills/` 是项目内**唯一真身**（附 `.agents/skills/.openspec-target` 记录已配置工具列表）；33 个 `universal` 工具直接读它，其余 54 个工具（`SKILL_LINKED_TOOL_IDS`）在各自目录（如 `.claude/skills/`、`.kiro/skills/`）下放指向真身的相对链接（Windows 或 `eve` 退化为拷贝）。Zed 由 `.zed` 或 `.agents/skills` 检测。

| 类型 | 本质 | 来源 / 当前状态 |
|------|------|-----------------|
| skill | agent 自动发现的能力说明书（**当前唯一形态**） | `getSkillTemplates()` + `generateSkillContent()`，经 `installReleaseSkills()` / `installSharedSkills()` 落盘 |
| command | 1.x 的 slash/prompt 入口文件 | **v2.0.0 起不再生成**；`getCommandContents()` + command adapter 仅留供 `reconcileCommandFiles()` 比对并清理未改动的旧文件 |

这些目录是投递层，不是项目事实。删除或重生成它们会影响 agent 能不能触发 workflow，但不会直接改变 `openspec/specs/` 或 `openspec/changes/` 的业务内容。

## store 与全局仓库注册

```text
<globalDataDir>/stores/    # macOS/Linux: ~/.local/share/openspec/stores/
└── registry.yaml          # 全局 store 注册表

<store-checkout>/
├── .openspec-store/
│   └── store.yaml         # store 身份 metadata（id, remote）
└── openspec/
    └── specs/             # store 自身的 specs，供其他项目 reference
```

项目通过 `openspec/config.yaml` 的 `references:` 声明依赖哪些 store：

```yaml
references:
  - platform-api
  - shared-schemas
```

agent 通过 `openspec context` 获取引用 store 的 spec 索引，不内联内容。

```text
<globalDataDir>/worksets/
└── worksets.yaml          # 个人保存的多仓库打开视图（纯本地，不共享）
```

源码入口：
- `src/core/store/`（foundation, operations, registry, git）
- `src/core/references.ts`
- `src/core/worksets.ts`
- `src/core/working-set.ts`
- `src/core/root-selection.ts`

## 判断 source of truth 的经验法则

| 你看到的文件 | 应该怎么理解 |
|--------------|--------------|
| `openspec/specs/**/spec.md` | repo 当前 capability spec |
| `openspec/changes/<name>/**` | 某次 repo-local change 的计划和 delta |
| `.openspec-store/store.yaml` | store 身份 metadata |
| `<globalDataDir>/stores/registry.yaml` | 全局 store 注册表 |
| `<globalDataDir>/worksets/worksets.yaml` | 个人保存的多仓库视图 |
| `<globalDataDir>/projects.json` | 本机用过 OpenSpec 的项目列表（仅供迁移参考，缺失不影响任何命令） |
| `<globalDataDir>/global-skills.lock` | 全局 skills 安装的跨进程互斥锁 |
| `~/.agents/skills/` 或项目 `.agents/skills/`（及工具链接） | 给 agent 的入口和说明，可重生成（1.x command 文件已于 v2.0.0 停产） |
| generated `.code-workspace` | editor 打开视图，可重生成 |
