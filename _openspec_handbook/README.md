# OpenSpec 学习手册

> **手册版本 v1.13** · 对齐 OpenSpec 1.14.3 · 2026-10。版本规则与变更记录见 [`00-index.md`](00-index.md) 的「版本与维护」。
>
> 各篇定位、结构、风格的硬约束见 [00-index《内容宪章》](00-index.md#内容宪章写作规范)——写新篇前先读。

按认知层次教你用好 OpenSpec：先会用，再懂概念，再看高级边界，最后进入实战和机器协议。每篇自成一体；本页集中维护高层阅读路线，章节本身不再附“下一步”跳转。

编号按**难度层级分配号段首位**：初级 `0N`、中级 `1N`、高级 `2N`、实战 `5N`；`00` 是导读，`90`/`99` 是附录与 FAQ。

术语上先记住一点：`openspec` 是终端 CLI 和文件状态机制。`/opsx:*` 是 Claude Code 等 command adapter 的入口，不是所有宿主的通用语法；Codex 使用 `$openspec-*` skills。`opsx` 不是另一个产品。

## 阅读路径

- **只想先用起来** → 01 → 10
- **想真正理解 OpenSpec** → 01 → 10 → 20 → 21 → 22 → 23 → 26
- **想懂 specs 怎么组织、为什么会漂、机器挡住哪些** → 10 → 26
- **想知道它到底强制什么、agent 每次看到多少** → 10 → 22 → 23 → 26
- **多仓库场景** → 01 → 10 → 20 → 21 → 24
- **要自定义工作流** → 21 → 23 → 25
- **main specs 很多，想选对合同** → 10 → 26 → 51 / 53 → `_digested/spec-driven-capability/`
- **想看实际怎么落地** → 50 → 51 → 52 → 53 → 54 → 55
- **研究底层机制** → 读完主线后加 90

完整的版本、术语、命令和逐篇文件地图只在 [00-index](00-index.md) 维护；不要依赖章节尾部的跳转来判断阅读顺序。

## 组织原则

编号按阅读难度和用途分段：

- `00-09`：导读与基础概念（`00` 索引、`01` 初级）
- `10-19`：中级
- `20-29`：高级思想和边界
- `50-59`：实战场景
- `90/99`：附录和 FAQ


这样排是为了让读者先建立 OpenSpec 的思想和边界，再看真实场景怎么用。
